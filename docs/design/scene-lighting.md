# Scene lighting and skyboxes

Add an optional scene `[environment]` table with linear ambient colour/intensity, linear background colour, a project-relative PNG/JPEG equirectangular skybox, rotation and brightness. Missing settings preserve the current white ambient light at 0.18 and dark background. Existing entity lights remain unchanged. Skybox pixels supply a background; image-based diffuse/specular illumination is outside this change.

SceneDefinition validates and resolves the bounded image before world construction. LoadedScene owns the resolved environment. GeometryRenderer owns one optional panorama texture/pass, outside entity identity; existing SlotMap handles still own geometry. Decode/upload happen at scene load, never during frame traversal. The background uses one fullscreen triangle before opaque geometry, reuses one uniform buffer, and reconstructs camera rays from the inverse view-projection; translation does not move the sky. Perspective and orthographic cameras are supported. Image limits reuse TextureImage: PNG/JPEG, 16 MiB, 4,194,304 pixels, max 4096 per axis; skyboxes require 2:1 dimensions.

The Lighting page edits a selected scene with revision checks, staged native validation and atomic publication using existing authoring tools. It includes global colour/intensity, background colour, skybox swatches, rotation/brightness and a native scene preview. Keep unsaved-change guards and shared navigation. Main inspection and gameplay consume the saved settings.

Image Generator gains Skybox beside Image/Sprite/Video. Existing project PNG/JPEG library assets use the same sidecar with a skybox kind; import, relabel, generation, explicit candidate promotion and deletion share existing code. Default FLUX Schnell uses a 1024×512 image size and a panoramic prompt. Custom model requests must expose a supported 2:1 size field before paid submission; never silently send a guessed model field. Imported/relabelled skyboxes must be 2:1 and native-decodable. A generated panorama can still have a visible seam; no seam repair or HDR/IBL is claimed.

Validate defaults and malformed settings, project containment/image budgets, scene round trips/conflicts, image-kind/generation inputs, and native rendered pixels for ambient/background/panorama rotation/translation independence. Browser smoke covers Lighting navigation/save/reload, main viewer and Skybox import/classification/options; no paid submissions.

Implementation uses nine GPU light slots to retain all eight authored lights plus global ambient; ProjectGeometry prepares the ambient light during upload. The existing inspection viewport has a read-only mode for orbiting the lighting preview without object edits. Native regression is `cargo run --release --all-features --example lighting_smoke`; it verifies rendered pixels, camera translation independence and orthographic sampling on the native adapter. Browser acceptance uses `scripts/lighting-smoke.ts` with a temporary standalone project and isolated IDE data.

FAL size contract checked against https://fal.ai/models/fal-ai/flux/schnell/api (2026-10-30): `image_size` accepts a custom width/height object. No paid request was made during validation.
