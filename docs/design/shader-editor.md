# Shader editor — SHADER-1

A project-owned schema-1 `.shader.toml` contains a bounded, ordered scalar DAG (at most 32 nodes and 16 exposed parameters), surface output bindings and opaque/alpha mode. Nodes reference earlier durable node IDs, never runtime keys. A material references the shader asset plus named parameter overrides. Existing material assets remain valid. The world still owns entities through SlotMap; the renderer owns compiled pipelines as part of its existing typed geometry resources. No new entity/ownership graph.

Loading validates names, ranges, references, arity, bounds and outputs before generating WGSL. No arbitrary user WGSL, loops, bindings or shader-stage entry points are accepted. Generated expressions are compiled on resource preparation, never per frame. The first implementation stores a pipeline with each shader-bearing geometry; sharing compiled pipelines is a later measured optimisation. Parameter data fits four vec4 uniforms; time is explicit and finite. The steady-state draw path does no parsing/compilation. Alpha surfaces render after opaque surfaces, sorted by object origin; triangle-level transparency and intersecting transparent surfaces are unresolved.

Outputs are colour, emission multiplier, opacity and displacement along mesh normals. Displacement does not alter physics and needs sufficiently subdivided meshes. Shader materials do not cast shadows in this slice; matching displaced/dissolved shadow passes, depth/colour sampling, refraction, shoreline foam and normal-map authoring follow later. Terrain blend layers reject custom shaders rather than silently ignoring them.

The IDE provides a project library, node cards with explicit input/output selectors, templates (force field, stylised water, dissolve), exposed scalar parameters, play/pause/time scrub, sphere/plane/cube previews, undo and validation errors that retain the last valid preview. Browser GLSL preview and native WGSL derive from the same bounded graph contract; native scene validation is authoritative on save. AI uses existing provider settings to return a validated draft, never publishes automatically; it can start before the first save. Materials are the application boundary, selected through existing material controls. Per-object overrides use inline material values; shared library materials remain shared.

Save uses existing project-scoped containment, revision guards, staged native candidate validation and atomic writes. Shader edits validate dependent scenes before publication. Tests cover invalid graphs, parameters, missing/stale references, material resolution, compilation and native pixels/time/displacement/alpha. Browser smoke covers template editing, save/reopen and material creation. No frame-time claim without a defined workload and measurement.

## Delivered: SHADER-2

**Node canvas.** The list of node cards is replaced by a wired canvas. A palette adds Input, Math and Pattern nodes. Each card shows its named inputs on the left and its one scalar output on the right; a Surface output card takes red, green, blue, emission, opacity and displacement. Dragging from an output socket to an input connects (an input holds one wire; an output fans out). Dragging a connected input away unplugs it. Connections that would make a loop are refused. Unconnected sockets are marked and named in the error, and the preview keeps the last valid graph. Delete removes the selected node; a keyboard inspector below the canvas edits the selected node's operation and inputs, or the surface outputs.

**File contract.** Unchanged except an optional editor-only `position = [x, y]` on each node and on `outputs`, validated as finite within ±100000 and ignored by compilation (a Rust test checks the WGSL is identical). The editor re-orders nodes topologically after each connection, so files still list inputs before their users. Graphs without positions (templates, AI drafts, MCP edits) are laid out automatically: columns by distance from the surface output, each node level with what it feeds. AI drafts keep the positions of nodes they kept.

**MCP.** `list_shader_nodes` returns node types with named inputs, the outputs, limits and templates. `describe` of a shader returns its nodes with named input connections, output wiring, parameters, revision and the files that use it. `create_shader` (from a template or a plain white surface) and `edit_shader` apply node-ID operations (`add_node`, `update_node`, `remove_node`, `connect`, `set_parameter`, `remove_parameter`) and then require every input and output to be connected. Saves go through the editor's path: engine validation of every project scene with a probe, a revision guard, dry run, journal (history and undo) and a live IDE refresh. `set_material` accepts a shader asset ref.

**Validation.** IDE unit tests cover layout, re-ordering, loop refusal and gap messages. An MCP integration test on a template-derived project covers discovery, dry run, create, edit, refused edits that leave the file untouched, a stale revision, applying through `set_material` and undo. The browser smoke adds palette, drag wiring, unplug, undo and loop refusal to the existing shader flow.

## Library and viewport layout

Shader assets use the shared thumbnail carousel across the top of the editor. Its sticky + New tile opens a plain, valid blank shader; starter force-field/water/dissolve graphs are loaded explicitly through the Load example picker. Library selection and example loading retain unsaved-draft confirmation. The library dropdown and new-effect buttons are removed.

On desktop the workspace fills the available viewport. The preview image stays fixed within the left card; playback, examples and AI controls scroll beneath it. The graph pane scrolls independently and sizes its canvas to the available card height. Narrow windows stack the cards. Graph −/+ buttons zoom about the viewport centre without changing authored positions; Fit all and center uses the bounds of all nodes and the surface output, allowing scales below the former fit floor. Wheel zoom does not scroll the surrounding controls.
