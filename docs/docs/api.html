Public surface · v0.10.0

Library and API.

A practical map of the functions and types available to a game today. Expand a method for its purpose and contract.

Foundation API: Emergent is evolving quickly. This guide records the checked-in 0.10.0 API; it does not promise long-term semantic version stability yet.

Nested UI layouts

The UI Designer palette includes Horizontal layout, Vertical layout and Grid layout. Select a container before adding widgets or another layout; use Move into and the outline ordering controls to rearrange the hierarchy. Each container has width/height lengths, padding, gap and main/cross alignment. Grid uses an integer column count and equal cells. Percent child dimensions refer to the row/column content box or grid cell. Automatic layouts manage positions; resize children or reorder them in the tree. Existing panel stacks remain compatible. Grid children support col_span/row_span, and dimensions accept auto for content sizing. Saved UIs can be placed with Add screen overlay or Add world panel; both render through the native host. Pointer interaction and action/value binding remain planned.

In-game UI surfaces

Save a UI in the designer, then use Add screen overlay or Add world panel. The scene receives an entity with emergent.ui. Screen surfaces composite after the 3D scene with alpha and no depth, ignore camera/entity transforms, and fill the viewport when width/height are zero. Explicit dimensions and x/y use pixels. World surfaces are unlit, depth-tested XY panels centred at their entity origin; width/height are metres, and entity transforms place them in the world. Default world width is two metres with canvas aspect ratio.

[[entities.components]]
type = "emergent.ui"
ui = "assets/ui/options.ui.toml"
space = "world"
width = 2.0
height = 1.5

The same prepared RGBA UI includes authored widget state and a built-in 5×7 uppercase ASCII bitmap font. Images are prepared once, not each frame; resize changes overlay projection. Limits: 4,194,304 pixels per surface and 64 MiB of scene UI pixels. The renderer owns ordinary generational GeometryId resources; entities retain World identity. Direct renderer consumers use UiSurface and GeometryRenderer::insert_ui_surface. Pointer/ray input, mutable values/actions, text editing and font shaping are not implemented. Reload a scene to apply asset changes. See native evidence and limits.

Prefabs

A prefab is a named project asset containing one root and its complete child hierarchy. Drag a scene parent into the Prefabs section to create a prefab using its current name. The library is a scrollable table: drag a row onto the scene root/empty graph to instantiate, or onto an existing node to parent it there. Enter on the capture area saves the selected object; Enter on a row instantiates at root. Each placement gets fresh durable IDs and its own name, hierarchy and internal component/brain links. Move, reference or delete the instance through its root; individual children remain selectable. The viewport placement picker also accepts prefabs.

let drone = emergent::PrefabDefinition::load_named(&project, "Drone")?;
let scout = drone.instantiate_as(&mut world, "Scout 1")?;
let wingman = drone.instantiate_as(&mut world, "Scout 2")?;
let body = scout.root;
let rotor = scout.entities["rotor-front-left"];

Exact label lookup rejects missing or ambiguous names; use load(project, path) for an explicit asset path. Discovery happens while loading; the loaded definition can spawn repeatedly without file I/O. Each construction returns LoadedScene with fresh World-owned SlotMap handles, a prefab-local member map, renderables and project components for the existing game integration. Entity links outside the graph are rejected. Bounds are 1,024 members and 256 KiB. Placement creates independent snapshots; asset defaults and media remain shared. Recursive prefabs and automatic propagation of definition edits are deferred. Audio is a separate planned capability. See the prefab format and contracts.

Particles and effect assets

ParticleDefinition is a versioned effect recipe with 1–16 ParticleEmitter layers. Point, cone, box and sphere shapes support seeded rate/burst emission, duration, local/world space, lifetime ranges, speed/spread, gravity/wind acceleration, drag, angular speed, and linear size/color/opacity transitions. Lengths are metres, time is seconds, and scale multiplies initial world-space positions, velocity and particle size; local particles follow the current emitter transform.

let definition = emergent::ParticleDefinition::load(&project, "assets/particles/smoke.particle.toml")?;
let effect = definition.resolve(&project)?;
renderer.prepare_particle_effect(&effect);
world.insert_component(entity, effect)?;
// Engine fixed updates synchronize components and advance particles.
renderer.set_particles(world.particles());
renderer.render_lit(&geometry_instances, &lights)?;

ParticleStore also works independently: insert(effect, model) returns an owner-scoped ParticleSystemId; set_transform, restart, remove, contains, live_count, step and read-only visit support custom consumers. Stale/foreign handles are rejected. step requires a finite delta in (0, 0.1] seconds; use a fixed loop such as PARTICLE_STEP (1/60 s). The World integration bounds unusually long fixed updates to at most 120 substeps and fails explicitly if their delta still exceeds this contract. A store reserves at most 100,000 live particles; full pools consume emission credit without accumulating a delayed burst.

Runtime particles use dense reusable buffers, never World entities. Emitter identities remain in SlotMap storage; serialized assets use durable IDs and paths. Effect resolution loads shared PNG/JPEG sprites off the frame path, with a 64 MiB decoded-image budget per effect. Grid dimensions must divide the image dimensions. Set columns, rows, frames, fps and random_frame for flipbooks. texture omitted uses a procedural soft circle.

The graphics feature supplies instanced camera-facing quads, texture alpha, sorted alpha/additive composition, depth testing without particle depth writes and soft_distance fading against opaque surfaces. Call prepare_particle_effect(&effect) during scene preparation to upload premultiplied sprites outside the frame loop. Empty frames retain this preparation cache; clear_particles frees it on scene teardown. Call GeometryRenderer::set_particles after setting the camera and before each render; clear_particles removes the retained frame. Sprite resources are shared, staged instance buffers are reused, and unused sprites are retired during extraction. GPU simulation, ribbons/trails, collision and volumetric fluids are deferred.

# Effect entity asset (.entity.toml)
schema_version = 1
id = "campfire"
kind = "particle-effect"
particles = "assets/particles/campfire.particle.toml"

Open /particles or the Particle Generator rail button to use Particle Factory. Save/update/copy effects into the header’s horizontal native-still swatch library. Select a swatch to load it; a dialog protects unsaved changes. Each swatch’s Add to scene action places its saved recipe without replacing the active draft. Effects also reopen through the selected instance’s Edit particle effect action. The main editor freezes an independent VFX preview at two seconds without advancing gameplay; Run uses actual fixed-step simulation. The browser generator preview approximates the native blend order and does not implement native soft-depth fading; use Capture native renderer to inspect the engine result.

The sprite/video workshop reuses saved server-side fal credentials and durable image jobs. Image-to-video and explicit transparent background removal are separately triggered paid stages. Imported/generated clips can be baked locally through ffmpeg/ffprobe into 32 padded frames (8 columns × 4 rows, 8 fps, four seconds, 256 px cells). Short clips hold their last frame. Soft alpha is checked before padding, opaque smoke is rejected, additive-only atlases are labelled, and source clips remain in the IDE job journal. Model IDs and source/job provenance accompany imported atlas assets; no runtime video decoder is required. Generated loop quality and smoke matting require visual review.

Terrain preparation

Optional native GPU diagnostics: gpu_timestamps_supported() reports the device feature. GeometryRenderer::profile_lit_frame(instances, lights) returns an optional GpuFrameProfile on offscreen renderers, with main/shadow GPU microseconds and separate CPU preparation, encoding and completion/wait timings. It blocks, uses retained diagnostic resources and reads timing counters without reading colour pixels. Main GPU timing includes sky/ray/mesh but excludes particles and final UI overlay composition; CPU completion includes the GPU wait and is not additive to GPU duration. Unsupported devices return None; invalid counters return an error. geometry_buffer_bytes(id) reports uploaded vertex/index buffer sizes for a live renderer-scoped handle, excluding material/driver memory. See GPU benchmark and measurement boundaries.

Ray terrain rendering uses conservative projected bounds and scissor rectangles by default, with full-viewport fallback at near-plane intersections. GeometryRenderer::set_raymarched_render_options(RaymarchedRenderOptions { bounds_culling, step_heatmap }) controls runtime diagnostics; defaults are true/false. raymarched_frame_stats() returns last-prepared region/submission counts and summed scissor areas, not GPU fragment counts. Debug options never change authored assets. The Terrain Builder live viewport offers Auto/Full/Half quality and a step heatmap; magenta marks iteration exhaustion. Capture timings include GPU completion/readback. See measurement limits and validation.

TerrainSettings is a serializable, validated recipe (default algorithm version 2; version 1 retained) for seeded independent terrain patches. Choose TerrainBase::Noise or TerrainBase::DiamondSquare, a TerrainPreset, resolution (32/64/128/256/512/1024 samples), extent/relief, mountain-group count, warp/ridge strength and 0–64 thermal erosion passes.

Experimental RaymarchedTerrain now defaults to version 2: size=1024 metres, biome_scale=180, relief=120, overhang=6 and cave_radius=8, plus a seed and a RaymarchedBiome. Explicit Plain, Hilly, Mountainous, Island, Rivers, Canyon, Underwater and CaveCavern choices select matching CPU/WGSL fields; missing biome preserves earlier Blend output. Extents 64–4096m clip a world-space field of plains, ridged mountains, rock overhangs and carved caves; they do not enlarge its features. Assets without a version retain legacy version-1 test shapes. bounds(), distance(point) and trace(origin, direction) expose reference geometry. GeometryRenderer::insert_raymarched_terrain(field) returns a renderer-scoped generational handle; transform/remove methods follow ordinary scene instances. Terrain Builder shares a Height Field / Ray March switch and biome modal. The ray-marched live viewport retains one native renderer for orbit, pan, zoom and projection commands, reusing bounded inspection sessions. Library save/load/placement remains revision guarded. Colours are procedural grass/rock/snow; physics collision and library material painting remain unsupported. Size limits are input bounds, not performance targets.

let recipe = emergent::TerrainSettings::default();
let field = recipe.generate()?;
let heights: &[f32] = field.values();
let mesh = field.mesh(emergent::Color::WHITE)?;

field.settings() returns its recipe; heights are row-major world-space Y values. Version 2 mountain groups have multiple uneven summits, saddles and broad shoulders; version 1 retains its original single-tip shape. recipe.comparison() returns original-noise, diamond-square and enhanced recipes with shared seed/extent/resolution. Generate and upload outside the frame loop; existing World/renderer owners retain SlotMap identity. Terrain entity assets now load through the normal scene path; optional static height-field collision uses the same versioned recipe. Seamless edges and streaming/LOD remain planned. Terrain Builder at /terrain consumes this API, compares grayscale meshes, and saves the displayed recipe as a terrain entity in the selected scene. [terrain] stores the versioned settings; UUID asset/instance identity is independent of display name.

Inspection math and picking

InspectionRay::from_viewport(view_projection, Vec2) unprojects normalized top-left-origin coordinates with WebGPU depth clipping. project_point performs the matching projection. GeometryRenderer::view_projection exposes the exact rendering matrix.

With the graphics feature, PickingMesh::from_geometry builds an optional CPU cache from the renderer's tessellation. intersect(ray, model) returns the nearest world-ray distance using bounds and double-sided triangle tests. The caller retains canonical EntityId ownership; picking caches carry no alternate identity.

TransformGizmo::begin(world, id, space, tool, axis, view_projection, start) captures a transform snapshot; update(cursor) returns a proposed local Transform and original() supports cancellation. TransformSpace::{Local, Global} and GizmoTool::{Translate, Rotate, Scale} choose semantics. Call after propagation. The first gizmo contract uses the fixed 960×540 inspection viewport. Updates do not mutate the world; the caller validates and applies them explicitly.

Noise filters

NoiseDefinition::load(project, path) and from_source validate schema-1 noise assets. NoiseSettings selects NoiseAlgorithm::{Perlin, OpenSimplex, Worley}, algorithm version, seed, field dimensions/size and octave/domain inputs. validate() checks finite bounds and the evaluation budget before generation.

NoiseGenerator::new(settings) prepares seeded sources once. sample_2d([x,y]) / sample_3d([x,y,z]) return normalized values in 0..1 without per-sample allocation. generate() returns an owned NoiseField with width, height, depth and x-fastest f32 values: x + width * (y + height * z). A 3D field is a complete cube. Prepare Worley generators per worker thread; the dependency's callback is local to the prepared source.

The headless noise_filter example validates project assets or emits a bounded ENF1 field for the IDE. Noise settings/fields are immutable data values, not additional entity identities. Future scene consumers keep canonical SlotMap ownership.

Diffuse images and terrain materials

MaterialDefinition.diffuse_map accepts MaterialTextureMap { asset, scale }, referencing a project-relative PNG/JPEG. Scale is repeats per local metre (0.001–100). Material texture_tiling = [x, y] independently multiplies the two sampled texture axes for both UV and triplanar projection. resolve(&project) prepares the active image; constant() rejects unresolved image references. TextureImage provides bounded native decoding, EXIF orientation, dimensions and RGBA8 bytes. Colour images sample as sRGB with gamma-correct mipmaps.

[material]
shading = "smooth"
albedo = [1.0, 1.0, 1.0]
texture_tiling = [2.0, 3.0]
[material.diffuse_map]
asset = "assets/textures/grass.png"
scale = 0.5

Object-space triplanar projection wraps images on primitives and terrain without UV attributes. Albedo/geometry colour and noise still tint the image. The renderer owns uploaded resources through existing GeometryId entries; decoding and mip preparation occur on load/upload, outside steady frame traversal. Initial images are opaque: PNG alpha does not produce cutouts or blending.

Legacy terrain_layers and active_layer remain readable. New terrain painting uses an entity-level terrain_paint = "assets/terrains/ground.paint.toml" reference. Its schema-1 TerrainPaint contains resolution, 1–4 library materials, three ordered height transitions, a blend width in local metres, and row-major RGBA byte weights. Each four-byte sample sums to 255; unused slots are zero. Resolution must match the terrain (32–256). TerrainPaint::validate() checks this contract. Native rendering blends all surface channels, using diffuse arrays capped at 1024 pixels and noise volumes up to 64³ per layer. The IDE offers manual soft painting, an explicit height-band process, undo and exact save/reopen. The browser diffuse preview is reduced-resolution; inspect natively for lighting, noise and bump. Slope rules remain planned.

Feedback control (preview)

emergent::control::{Pid, PidConfig, PidInput, PidOutput} supplies a reusable scalar controller without physics or graphics features. Each object owns one instance per controlled scalar. Configuration is validated on construction; gains use seconds, and step receives the simulation duration explicitly. It returns P/I/D contributions, requested/clamped output, internal saturation and actuator tracking error. No allocation occurs during stepping, reset or error handling.

use emergent::control::{Pid, PidConfig, PidInput};
let mut pid = Pid::new(PidConfig { kp: 2.0, ki: 0.5, ..PidConfig::default() })?;
let command = pid.step(PidInput {
    setpoint: 5.0,
    measurement: 4.0,
    ..PidInput::default()
}, std::time::Duration::from_secs_f64(1.0 / 60.0))?;
// Default output bounds are -1..1; choose bounds and gains for your signal's units.
let output = command.output;

Derivative is filtered measurement derivative, so setpoint changes do not cause derivative kick. Feedforward is caller-supplied. Optional achieved_output is the actuator's total output during the preceding control interval, expressed in this controller's output units; it drives anti-windup alongside internal clipping. Invalid samples or arithmetic leave state unchanged. reset() clears history. Do not step paused/disabled controllers; reset on re-enable, body reconstruction or teleport. Gain changes construct a fresh controller. A full goal-based physics drone is still planned. See the control contract.

Physics (preview)

Enable emergent = { path = "../..", features = ["physics"] } for headless Rapier simulation; add graphics separately for rendering. Attach a PhysicsBody component through World::insert_component. BodyKind::Static stays fixed; BodyKind::Dynamic responds to gravity and contacts. BoxCollider supplies local center: [f32; 3] and positive half_extents: [f32; 3].

let collider = BoxCollider { center: [0.0; 3], half_extents: [0.5; 3] };
let body = PhysicsBody::new(BodyKind::Dynamic, collider)?;
world.insert_component(entity, body)?;

PhysicsBody.collider is now Collider::Box(BoxCollider) or Collider::Terrain(TerrainCollider). Existing PhysicsBody::new(kind, BoxCollider { ... }) calls remain valid. Use collider.as_box() to inspect box dimensions. For terrain, PhysicsBody::new(BodyKind::Static, TerrainCollider { settings: recipe }) builds a static heightfield from the render recipe on insertion/settings/scale changes. Dynamic terrain bodies are rejected.

Public settings are gravity_scale (0..100, default 1), mass (0.0001..1000000 kg, default 1), friction (0..10, default 0.5), and restitution (0..1, default 0). validate() rejects invalid settings. Gravity is currently fixed at [0, -9.81, 0] metres/second squared. The engine steps after gameplay/behaviours and lifecycle commit, before final propagation and PostFixed. Timesteps must be at most 0.1 seconds when physics bodies exist.

World::add_force(entity, force) submits world-space newtons; World::add_torque(entity, torque) submits world-space N·m. Commands sum for the next fixed step and are cleared between steps; resubmit for sustained force/torque. They require a dynamic body and reject nonfinite/overflowing commands. World::linear_velocity and World::angular_velocity (physics feature) read the last committed backend state in m/s and rad/s, or None before initialization. Reads reconcile component edits on the next fixed step. Torque changes angular acceleration; it does not prescribe orientation.

World::physics_body_state(entity) (physics feature) returns a copied PhysicsBodyState: committed transform, linear/angular velocity, actual mass, effective gravity and reconstruction revision. It returns None before initialization or while current body settings/pose differ from committed state. A changed revision tells a controller to reset history for that same EntityId; it is not durable identity. PHYSICS_GRAVITY is the shared backend gravity constant; effective body gravity includes its gravity scale.

Unpowered physical locomotion boundary

A locomotion profile with type = "drone_physics" is loadable with the physics feature and an enabled dynamic body. It currently has no tuning fields or powered pilot: game code supplies forces/torques, and an unpowered body falls. It never writes its pose or follows brain flight commands. The catalogue marks it boundary; the editor labels/disables it and powered preview returns an explicit not-implemented error. The six existing movement types remain available.

LocomotionAgent::physics_state() exposes the last synchronized observation before post-fixed observers run. Motion history resets on missing/new body revisions. Scene/runtime validation rejects competing pose/velocity writers and requires positive uniform local scale for this type. Brain self/neighbour feedback uses measured physical velocity; physical brain look goals are rejected until a pilot can carry out heading requests. See the implementation contract and FLIGHT-2 evidence.

Dynamic bodies must be roots, optionally beneath a top-level identity scene container without physics. Positive-scale TRS is required; shear/reflections are rejected. Dynamic poses belong to physics; competing game transform writes return EngineError::Physics. Body/scale changes rebuild the body and reset velocity. Deletion or component removal removes backend resources at the next fixed boundary. Backend handles remain private; EntityId is canonical.

Entity assets accept [physics] defaults; [entities.physics] is a complete instance override, and enabled = false disables inheritance. Missing collider bounds are fitted from geometry, with a 0.01 metre minimum local half-extent. Explicit [physics.collider] accepts shape = "box", center and half_extents, or shape = "terrain" for a terrain asset with body = "static". Terrain colliders use the generated surface without box dimensions. Inspection is paused; the inspector saves instance settings and restarts inspection; box colliders show yellow outlines and terrain collision follows its mesh. Run uses a transient world and never persists simulated positions. See design and limits.

Materials (preview)

Object shadows: cast_shadows and receive_shadows are independent booleans on MaterialDefinition, both true by default. A non-caster remains visible and can receive shadows; a non-receiver can still cast onto other surfaces. Unlit objects can cast but ignore received lighting. The Material inspector exposes both controls; Edits save automatically after a short typing pause and refresh inspection. Collider outlines do neither.

Use a shadow-enabled directional or point light. The renderer supports one selected directional map (2048-square) plus two point-light shadow maps (six 512-square views each). Point maps follow the light position and range in every direction; point lights require range 0.01..1000000 and world coordinates within +/-1000000 when casting shadows. More than two shadow-enabled point lights returns an explicit error. Spot shadows remain planned. Try Point shadows — lamp and cube or Shadows — cast and receive. See object shadow controls.

MaterialDefinition is a headless authored contract: shading (flat/smooth/unlit), optional albedo override, specular, shininess (1..256), emission, emission_intensity (0..100), and bump_strength (0..2). Colours use linear RGB in 0..1. The IDE's sRGB colour pickers convert automatically. Default albedo uses geometry colours; default specular/emission are zero.

let material = MaterialDefinition {
    shading: MaterialShading::Smooth,
    albedo: Some([0.2, 0.5, 0.8]),
    specular: [0.6; 3],
    shininess: 48.0,
    ..Default::default()
}.constant()?;
world.insert_component(entity, material.clone())?;
let geometry_id = renderer.insert_with_material(&geometry, &material)?;

constant() validates materials with no noise references. resolve(&project) resolves MaterialNoiseMap { asset, strength } for albedo_map, specular_map, emission_map and bump_map. Each map refers to an existing contained .noise.toml asset; strength is 0..1. Material::definition() and noise_settings() expose immutable CPU data. GeometryRenderer owns uploaded resources under its scoped SlotMap GeometryId. Reinsert to change settings.

Noise is baked once into a packed RGBA16Float volume with linear filtering. noise_resolution selects 32 (default), 64 or 128 samples per axis; storage is 256 KiB, 2 MiB or 16 MiB when maps are assigned. A material-wide budget of 8,388,608 octave evaluations rejects expensive combinations before baking. 2D fields project onto object-local XZ, 3D onto XYZ; local bounds normalize coordinates across each object. The filter's seed, domain extent, offset and octave parameters are retained, with selectable material resolution. Smooth spheres use radial normals; bump uses an object-space gradient projected onto the smooth tangent plane. Emission brightens the surface; bloom and emissive scene lighting are future work. The first specular model is Blinn-Phong, with metallic/roughness PBR deferred.

Use inline [material] on entity assets or [entities.material] scene overrides for backward compatibility. Shared materials use MaterialDefinition { asset: Some("assets/materials/stone.material.toml".into()), ..Default::default() }.resolve(&project). A schema-1 material asset has an authored id, name and inline [material] table. References cannot contain inline overrides; nested material/paint references inside library assets are rejected. In the IDE, create and edit all surface settings in Material Generator, then select a library material on the object. Existing inline definitions can be copied into new library entries. Shared saves validate affected scenes before publication. See material library and painting design.

Editable structure meshes (preview)

StructureDefinition retains a versioned local authoring hierarchy of StructurePart values with durable IDs, optional parent IDs, StructureTransform (translation, XYZ rotation degrees and scale) and PolygonMesh (shared vertices and polygon index lists). PolygonMesh::triangulate_face uses bounded dominant-plane ear clipping. StructureDefinition::load(&project, asset) validates contained source; mesh() compiles the hierarchy into an ordinary indexed Mesh, preserving reflected winding. Authored scene loading

SceneDefinition::load(&project, path) parses and validates a schema-1 candidate without changing the world. instantiate(&mut world) returns a LoadedScene containing the root, durable-instance-ID lookup, CPU renderables and light entity handles. Construction failure removes the candidate subtree. Loading is explicit setup work; no file I/O is added to fixed updates.

EnvironmentDefinition is the optional scene [environment] contract: linear ambient_color and ambient_intensity, background_color, optional project-relative PNG/JPEG skybox, skybox_rotation in degrees and skybox_intensity. resolve(&project) validates and decodes a bounded 2:1 panorama into SceneEnvironment; LoadedScene.environment retains it. GeometryRenderer::set_environment(&environment) uploads the background once during preparation. Pass environment.settings.ambient_light()? alongside authored lights; the renderer supports eight authored lights plus scene ambient. Skyboxes are LDR backgrounds and do not provide image-based illumination.

SceneError exposes the source path and diagnostic. Supported content is bounded primitives, existing light types and empty hierarchy nodes; unknown fields/types fail. See the project guide for format and limits.

SceneDefinition::from_source(&project, path, source) validates an editor candidate against the project assets without replacing the authored scene. Instances accept an optional name display override (1–64 printable Unicode characters) in each [[entities]] table. It takes precedence over the shared asset name without changing IDs, parent links or asset paths. Omit it to inherit the asset name. Instances also accept optional [entities.transform] vectors; omitted vectors inherit asset defaults, and supplied vectors replace them before normal transform and hierarchy validation.

GeometryRenderer::set_view(eye, target, up) changes the render view without replacing world or geometry resources. Invalid, non-finite or degenerate camera bases return GraphicsError::InvalidView and preserve the existing view. EulerRot is re-exported with the existing math values for consistent scene rotations.

Camera authoring

GlobalTransform::look_direction() returns normalized world-space local -Z, or None for a degenerate transform. The inspector displays this derived look-at vector, including parent transforms. GeometryRenderer::view_transform() and projection() expose the actual renderer camera for inspection tools; PickingMesh::bounds() exposes cached local-space bounds.

With a scene instance selected, press F to frame its bounds with the editor camera. Press Shift-F to place the object at the editor camera's position and orientation while preserving its scale. Alignment persists through the normal validated scene override workflow. Shortcuts ignore text fields and dialogs; parent conversions requiring shear are rejected without saving.

Camera assets support perspective projection with field_of_view_degrees, or orthographic projection with view_size (vertical world-space height). Both require 0 < near < far <= 1000000. The schema accepts isometric and orthographic for orthographic projection; orientation is controlled by the camera transform. Optional [entities.camera] settings override a camera asset on an individual instance.

Select a camera instance to edit these fields live and see its frustum in the scene overlay. Select the camera asset under Project files to edit shared defaults. CameraProjection::frustum_corners(aspect) returns eight local-space near/far corners looking down -Z, without transform scale. The inspection overlay uses the viewport aspect ratio and stays out of the game render.

Tweens and easing

lerp(from, to, progress) provides ordinary scalar interpolation (including extrapolation). Easing provides Linear, Sine/Quad/Cubic In, Out and InOut curves. Tween::new(TweenSettings) validates an immutable recipe; sample(elapsed_seconds: f64) returns a scalar at explicit simulation time without allocating on successful samples.

use emergent::{Easing, Tween, TweenPlayback, TweenSettings};
let movement = Tween::new(TweenSettings {
    easing: Easing::SineInOut,
    duration_seconds: 2.0,
    from: -3.0,
    to: 3.0,
    playback: TweenPlayback::PingPong,
})?;
let x = movement.sample(1.0)?; // midpoint: approximately zero

Negative time holds the start; non-finite time is rejected. Once holds the end, Loop restarts, and PingPong reverses; duration is one direction. A behaviour owns its clock and applies values through existing World APIs. TweenDefinition::load(&project, path) loads schema-1 .tween.toml assets. Open the IDE’s /tweens editor to compare moving previews, scrub and save a selected variant. Saving creates a new reusable asset and does not automatically attach animation to a scene instance.

First-person controller

Use emergent.character_controller on an upright dynamic root body and emergent.mouse_look on its active child camera. Mouse look fields are sensitivity (degrees per raw pixel, default 0.12) and pitch_limit (degrees, default 85). In native Run, click to capture; WASD moves, Space jumps from supporting contact, Escape releases. Losing focus clears input. Hosts can queue raw deltas with Engine::add_mouse_motion(Vec2) and clear held keys and pending motion with Engine::clear_input(). Motion is consumed once per fixed tick without frame-time scaling.

The standard template includes assets/scenes/first-person.scene.toml and assets/prefabs/first-person.prefab.toml. Box and static heightfield terrain collision are supported. Capsules, automatic stairs, moving-platform attachment and ray-marched terrain collision remain open.

Physics inspector edits apply to the retained scene preview in place: collider/body attributes and their outlines refresh without a worker restart. Existing Rust save validation is retained. Saved settings take effect in a separate native Run session when it is next started.

Surface shader assets

Schema-1 .shader.toml files define an ordered scalar DAG of at most 32 nodes and 16 parameters. Material settings reference a project shader path, disable cast_shadows, and optionally supply a shader_parameters table. Outputs control RGB, emission, opacity and displacement along mesh normals. ShaderDefinition::validate, parameter_values and wgsl share the native contract.

Open Shader Editor, select a template, edit nodes/parameters or ask AI, then Save and Create material. Choose the resulting library material in an object's Material inspector. Native Run supplies fixed-simulation time; custom hosts use GeometryRenderer::set_shader_time. Resource preparation compiles the shader; no graph compilation occurs in rendering. Transparent objects sort by origin. Custom shaders do not cast shadows; displacement does not change collision. Texture graph nodes, scene depth/refraction, normal outputs and gameplay parameter bindings remain open.
