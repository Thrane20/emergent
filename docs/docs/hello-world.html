GuideHello World

One scene. One entity. One behaviour.

Move your first entity.

This complete game creates a scene, attaches a linear-motion behaviour to a child entity, observes its propagated transform, and exits after 120 fixed ticks.

Run the checked-in example

Terminal
cargo run --example hello_world

The output begins with Hello, Emergent! and reports the entity's X position every 30 ticks.

The complete program

examples/hello_world.rs
use emergent::{BehaviorSpec, Engine, EngineConfig, EngineContext, EntityId, Game, Vec3};

#[derive(Default)]
struct HelloWorld {
    mover: Option<EntityId>,
}

impl Game for HelloWorld {
    fn start(&mut self, context: &mut EngineContext<'_>) {
        let scene = context.world.spawn("Hello scene");
        let mover = context
            .world
            .spawn_child(scene, "Hello mover")
            .expect("the scene accepts its child");

        context
            .world
            .add_behavior(
                mover,
                BehaviorSpec::linear_motion(
                    Vec3::ZERO,
                    Vec3::new(1.0, 0.0, 0.0),
                )
                .expect("finite motion"),
            )
            .expect("the entity accepts its motion behaviour");

        self.mover = Some(mover);
        println!("Hello, Emergent!");
    }

    fn fixed_update(&mut self, context: &mut EngineContext<'_>) {
        if context.tick >= 119 {
            context.request_exit();
        }
    }

    fn after_fixed_update(&mut self, context: &mut EngineContext<'_>) {
        if context.tick.is_multiple_of(30) {
            let position = context
                .world
                .global_transform(self.mover.expect("the game has started"))
                .expect("the mover remains alive")
                .translation();
            println!("tick {:>3}: x = {:.2}", context.tick, position.x);
        }
    }
}

fn main() -> Result<(), Box<dyn std::error::Error>> {
    Engine::new(EngineConfig::default())?
        .run(&mut HelloWorld::default())?;
    Ok(())
}

What happens each tick

1 · Own

Spawn identity

World::spawn and spawn_child return world-scoped, generational EntityId handles.

2 · Compose

Attach behaviour

LinearMotion owns its current position and velocity, and stages one transform write per tick.

3 · Observe

Read after propagation

after_fixed_update runs after behaviour commit, lifecycle processing, and global transform propagation.

Try changing it

Change the velocity to move diagonally:

Rust
BehaviorSpec::linear_motion(
    Vec3::ZERO,
    Vec3::new(1.0, 0.5, -0.25),
)

Or replace the wall-clock run with an exact, non-sleeping test run:

Rust
let mut engine = Engine::new(EngineConfig::default())?;
let mut game = HelloWorld::default();
engine.run_ticks(&mut game, 120)?;
Snapshot rule: when behaviours are linked, every target reads the source's previously committed output. Link order cannot cause recursive same-tick execution.
