GuideGame projects

Engine boundary · project ownership

Build on Emergent.

A game is an independent Cargo package. It depends on Emergent's public API while owning its code, generated modules, assets, entry scene declaration, and selected platform outputs.

Run the reference project

Terminal · repository root
cargo run -p emergent-first-project

The executable loads and validates its emergent.toml, reads a project-owned speed value, constructs a linked behaviour scene and point-light entity through public engine APIs, and opens a native lit preview containing moving cubes, a ground plane, and a pyramid. Use -- --headless for the bounded 120-tick non-windowed check or -- --smoke for native presentation validation.

The Emergent IDE also exposes a preview Run control in its top bar. It starts the linked project's local Cargo development executable, reports build and completion state, and becomes a Stop control while the process is active. It does not yet select target outputs or provide visual project-mode pause and stepping.

Current boundary: the manifest and schema-1 scene/entity files are validated and loaded. Primitive, light and empty hierarchy nodes are supported; nested compositions and authored behaviour links remain planned.

Implement entity intentions

Select an entity definition, add a statement describing its intended behaviour, and save it. The IDE checks it immediately against existing project evidence. If it is missing, press Implement: the AI searches current project code and the linked foundation, reuses existing helpers where possible, generates project changes, and compile-checks them in a temporary copy before applying them. An independent check then updates the statement.

Reuse & changes records the reused symbols and changed files. Compilation and AI evidence are separate from runtime verification. For example, the reference cube uses a reusable project rotation helper at 15°/second; its focused tests verify the rate and preserved translation/scale. Use Run to see it spin; a tick-zero scene capture is stationary.

Make an asset appear in a scene

Select the scene, choose Add asset, pick a primitive or light, and leave Include in selected scene checked. Edit the entity file's transform, dimensions or colour in your code editor and press Load again. Native Run loads the manifest entry scene through the same construction path. Failed inclusion keeps the asset and reports the error.

The first loader supports 1,024 instances, eight lights, 256 KiB files and at most 32 subdivisions per primitive axis, with primitive dimensions capped at 1,000,000. It validates paths, types, values, duplicate IDs and parent cycles before creating runtime entities. Instances can share an asset; per-instance transform overrides are supported; nested compositions and authored behaviour ports remain future work.

Place, parent and transform instances

The left Scene graph lists the selected scene's authored instances. Project files remain in a collapsed section below it. Select an instance to edit Position, XYZ Rotation in degrees and Scale. Uniform scale links the three axes; Apply to scene validates and saves an override, then updates the preview. Reset to asset defaults removes the override.

Drag an instance onto another to make it a child, or onto Scene root to unparent it. The inspector Parent selector provides keyboard access. Local values stay unchanged on reparenting, so world placement can change. Parent translation, rotation and scale affect every descendant. Cycles, missing parents and stale edits are rejected.

The header Local / Global switch selects inspector coordinates. Global edits use Rust world transforms and save equivalent parent-local values under [entities.transform]. A rotated child under nonuniform parent scale can have shear: Global then exposes position only. Rotation/scale edits that require local shear fail without approximating the transform; use Local to edit those axes. Picking and axis gizmos are available during Inspect; undo/redo remains planned.

Edit scene and entity TOML

Open TOML beside Overview, Connections and Source. For an instance, choose Scene overrides or Entity asset. A scene override affects that instance; a shared entity edit affects every referencing instance. Save validates a staged copy of the project and all authored scenes before publishing only the edited document. Invalid source and external-edit conflicts preserve the existing files and your draft. Reload discards a draft with confirmation. Use Load or Restart inspection to apply whole-file source changes to the rendered scene.

Inspect a live, time-stopped scene

Select a scene and press Inspect. One native Rust process keeps its world and renderer alive while gameplay stays at tick zero. Drag to orbit, Shift-drag to pan, scroll to zoom, or use Reset view. Select an instance and Apply to scene to save and update its transform without restarting that process.

Restart inspection reloads code, geometry, scene membership and external asset changes. Stop inspection ends the owned worker; normal game Run is independent. Load remains the snapshot fallback. Browser disconnects expire after about 30–35 seconds without traffic.

Prototype bounds: latest-frame 960×540 PNG delivery, targeting 30 Hz. Current local release measurements delivered about 30 fps. This is not hardware video or a security sandbox. Axis gizmos preview drags before saving; gamepad input, general undo/redo and hardware video remain planned.

Pick and manipulate objects

Press Inspect, then click a visible object. Rust tests the rendered triangles and selects the nearest hit. Light and empty-node origins have editor markers. The scene graph and inspector follow selection. Click empty space to deselect; dragging the scene still orbits, Shift-drag pans and the wheel zooms.

Choose Translate, Rotate or Scale above the viewport. Drag a coloured X/Y/Z axis or rotation ring; the header Local / Global switch controls coordinates. Local translation follows the parent axes; local rotation and scale follow the object axes. Focused handles accept arrow keys for small edits. The preview updates while dragging, and release validates and saves the final local transform once. Escape or pointer cancellation restores the starting transform. A stale scene/asset revision rejects publication and restores the preview.

Near-parallel handles are hidden; change the view to expose them. Global scale handles act along world axes about the object pivot. On a rotated object, a nonuniform world-axis scale can require shear; that edit is rejected. Use Local mode for object-axis scaling. Global rotation edits that require local shear are also rejected. The caption shows delivered fps against the 30 fps target. The current tools edit one authored instance at a time. Snapping, multi-select, plane/free handles and undo/redo remain later work.

Load a scene into the IDE

Use the top-bar Scene viewer dropdown to select a scene, then press Load. The IDE compiles and launches the linked Rust project, constructs its registered scene at tick zero, and displays a PNG captured by Emergent's wgpu renderer in the central canvas. Gameplay remains stopped. Press Load again to regenerate the frame after code changes; a failed load retains the last valid image.

The first bridge captures a fixed-camera frame rather than streaming simulation. Scenes load explicit [[entities]] entries with unique id, an asset path, and an optional parent instance ID. No builder is needed for a data-only scene. The optional emergent.first-project.generated.main_scene builder adds the reference motion chain. Standalone GLB previews in Object Creator use a browser viewer and do not imply that the native renderer can load GLBs.

Terminal · repository root
cargo run -p emergent-first-project -- --preview-scene assets/scenes/main.scene.toml --preview-output /tmp/emergent-scene.png

Create and inspect noise filters

Choose Add asset → Filters → Noise function, name it and create it. Noise filters are reusable data resources, so they are listed under Project files and are not inserted as scene instances. Selecting a .noise.toml file opens its controls in the right inspector and a larger preview in Overview.

Start with Perlin for smooth gradient noise. OpenSimplex provides another organic gradient pattern; Worley produces cellular distance patterns. Edit Seed, Frequency, Octaves, Lacunarity, Persistence, Domain extent and XYZ Offset. New seed chooses an explicit seed you can retain. The same algorithm version, seed and inputs reproduce the same field.

Choose a 2D field or 3D volume and its resolution, then Generate preview. Rust generates every sample of the field. A 3D volume has a Z slice slider for its XY planes. Samples map directly to grayscale: black is 0, white is 1; there is no per-image contrast stretching. Dimensions, sample count and value range are shown.

Preview generation uses draft inputs without writing the asset. Save settings validates and stores them in assets/filters/<name>.noise.toml; the TOML tab edits the same definition. External changes reject a stale save. Invalid settings retain the last valid preview. The first limits are 512×512 for 2D, 128³ for 3D, 1–8 octaves and 2,097,152 total octave evaluations; reduce resolution or octaves if a request exceeds that budget.

Generated fields remain transient buffers. Terrain/material consumers, baked exports and filter-composition graphs are later work.

Create model assets

Open Object Creator (◇) in the IDE navigation. Configure a funded fal API key under Settings → Object generation, name your object, and upload a PNG, JPEG, or WebP reference image up to 10 MiB. Generate submits a paid TRELLIS image-to-3D request. Progress and candidates are retained in the IDE's local data directory across restarts.

Inspect the GLB using orbit, zoom, and Reset view, then choose Save to project. The model, original reference, and object.asset.json provenance descriptor are saved together under the first declared asset root's models/<name>/ folder. Select the model or descriptor under Project files to reopen its preview and inspect its dependency connections.

Preview evidence: mocked generation, browser rendering, saving, and reopening have been tested. Live fal generation still needs a configured key. Browser GLB preview does not add runtime model importing or make the object appear in the native game on Run.

Project

Authored ownership

The game owns source and assets. Engine internals remain private, and engine source does not change for each game.

Generated

Reviewable Rust

AI-generated modules are ordinary files under src/generated and use only public Emergent handles and APIs.

Portable

Validated paths

Project paths are relative, remain within the project root, and use portable names without parent traversal.

First light: the generated scene resolves the authored key-light definition to a canonical child entity carrying a LightSource component. It contributes to bounded lighting. With casts_shadows = true, a point light now renders a six-face shadow map; object material cast/receive flags still apply.

Manifest contract

emergent.toml
schema_version = 1
id = "emergent.first-project"
name = "Emergent First Project"
entry_scene = "assets/scenes/main.scene.toml"
generated_code = "src/generated"
asset_roots = ["assets"]

[[outputs]]
id = "macos-arm64-dev"
os = "macos"
architecture = "aarch64"
rust_target = "aarch64-apple-darwin"
profile = "development"
enabled = true

An output records intent. This iteration exposes and validates output declarations; it does not cross-compile, package, sign, or prove a target runtime.

Contract for code builders

  1. Read before editing

    Inspect emergent.toml, project AGENTS.md, existing generated modules, and the capability catalogue.

  2. Use canonical handles

    Build entity and behaviour graphs through public World APIs. Never serialize SlotMap or Bevy entity keys into assets.

  3. Keep assets declarative

    Put project data beneath a declared asset root and generated Rust beneath the configured generated-code directory.

  4. Validate the whole project

    Run workspace tests and the project binary so manifest, asset, generated-code, and runtime boundaries are checked together.

Generate project textures

Open Texture Creator at /textures, enter a surface prompt and generate 1–4 candidates using the saved fal key. Choose images and Add selected to project. Native-validated PNG/JPEG assets then appear in object diffuse and terrain material layer pickers. Provenance sidecars record the prompt, seed and provider request; credentials remain IDE-local. Tile-friendly prompting helps repeated surfaces but does not guarantee seamless edges. Brush painting and height blending remain future work.
